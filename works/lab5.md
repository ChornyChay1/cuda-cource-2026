## На чём фокус

Это итоговая работа: собираем и обучаем свёрточную сеть из библиотечных и собственных операций. Здесь важно одновременно удержать корректность слоёв, процесс обучения и движение данных между ними. Производительность будем оценивать не только для отдельного ядра, но и для шага обучения целиком.

## Что означает «собрать руками»

Вы сами организуете параметры и промежуточные буферы, forward/backward слоёв, вычисление градиентов и обновление весов. Писать все оптимизированные свёртки, pooling и их backward с нуля не нужно.

- **Можно брать из библиотек:** свёртки, pooling, активации и их backward из cuDNN; matmul из cuBLAS; вспомогательные операции из Thrust и подобных библиотек; готовый загрузчик датасета.
- **Нужно написать самим:** LayerNorm с backward, устойчивые softmax/cross-entropy с backward и exclusive Scan для отбора индексов ошибок.
- **Нельзя использовать в основном обучении:** готовую AlexNet из model zoo, предобученные веса, autograd и готовый training loop. Для проверки можно собрать эталон из готовых слоёв и функций, включая autograd. Он должен повторять вашу архитектуру и получать те же входы и веса, но не требует собственной C++-реализации.

## Архитектура и данные

Работаем с CIFAR-100: RGB-изображения `32×32` и 100 классов. Большую AlexNet нельзя просто перенести на это разрешение без изменений, поэтому используем **AlexNet-style**: пять свёрточных и три полносвязных слоя. LayerNorm — наша добавленная модификация.

Ниже базовый компактный вариант. Размеры указаны без оси батча; после каждой свёртки используется ReLU.

| Этап                        | Параметры                                                     | Выход       |
| --------------------------- | ------------------------------------------------------------- | ----------- |
| Вход                        | RGB                                                           | `3×32×32`   |
| Conv 1 + ReLU + MaxPool     | 64 фильтра `3×3`, stride 1, padding 1; pool `2×2`, stride 2   | `64×16×16`  |
| Conv 2 + ReLU + MaxPool     | 192 фильтра `5×5`, stride 1, padding 2; pool `2×2`, stride 2  | `192×8×8`   |
| Conv 3 + ReLU               | 384 фильтра `3×3`, stride 1, padding 1                        | `384×8×8`   |
| Conv 4 + ReLU               | 256 фильтров `3×3`, stride 1, padding 1                       | `256×8×8`   |
| Conv 5 + ReLU + MaxPool     | 256 фильтров `3×3`, stride 1, padding 1; pool `2×2`, stride 2 | `256×4×4`   |
| Flatten                     | —                                                             | `4096`      |
| Linear 1 + LayerNorm + ReLU | `4096 → 512`; нормализация по 512 признакам одного объекта    | `512`       |
| Linear 2 + ReLU             | `512 → 256`                                                   | `256`       |
| Linear 3                    | `256 → 100`                                                   | 100 логитов |

Размеры фильтров, число каналов, ширину полносвязной части и положение нормализации можно изменить, если вы объясните решение и укажете получившиеся размеры тензоров. Сохраните пять свёрточных и три линейных слоя, собственную LayerNorm, вход `32×32` и 100 классов. Для сравнения нужна та же архитектура, а не стандартная AlexNet другого размера.

Из обучающей части выделите validation для подбора гиперпараметров. Официальный test оставьте для итоговой оценки. Если считаете статистики нормализации, используйте только примеры, оставшиеся для обучения после выделения validation. Validation и test в расчёт не включайте. Можно также взять заранее фиксированные значения из указанного источника.

## Собственные операции и обучение

- Реализуйте LayerNorm: среднее и дисперсию по выбранным осям, `epsilon`, обучаемые `gamma`/`beta`, backward по входу и обоим параметрам. В базовой сети нормализуем строку из 512 признаков; дисперсию считаем с делением на число признаков, без поправки на несмещённость.
- Реализуйте построчный softmax по 100 классам с вычитанием максимума. Cross-entropy считайте устойчиво из логитов, не через логарифм уже округлённых вероятностей.
- Для softmax/cross-entropy можно написать объединённый backward. Полный якобиан softmax материализовывать не нужно. Loss усредняйте по фактическому размеру батча.
- Свяжите операции в forward/backward и обновление параметров. Начните с SGD из Lab 4; другой оптимизатор допустим, если вы опишете его состояние и правила обновления.
- Обучите сеть с нуля: одного шага на одном батче недостаточно. Укажите число эпох, размер батча, обработку неполного батча и learning-rate schedule.
- Сохраняйте веса и проводите итоговую оценку на загруженной модели без обновления параметров.

Собственные операции сначала проверьте в FP32. Mixed precision и другие улучшения можно добавлять после проверки базового варианта.

## CLI и форматы файлов

```bash
./build/submission --mode train --input train.bin --output model.ckpt
./build/submission --input test.bin --output predictions.txt
./build/submission --mode eval --input test.bin --output predictions.txt
```

Оба вызова `eval` равнозначны: проверка запускает один без `--mode`, другой с `--mode eval`.

Как и в [Lab 4](lab4.md#cli-и-форматы-файлов), используются два режима:

- **`train`** обучается с нуля на переданных fine-метках, старые веса не нужны. В `--output` запишите один непустой обычный файл весов до 128 МиБ включительно, без символьных ссылок и дополнительных жёстких ссылок на этот файл. Формат весов выберите сами.
- **`eval` (по умолчанию)** загружает `model.ckpt` из каталога файла `--input`, не меняет веса и пишет в `--output` по одному предсказанному классу на строку в порядке входа (`0`–`99`, одна или две десятичные цифры, без знака и заголовка). Список ошибок из Scan проверьте отдельно; в файл предсказаний его не добавляйте.

Оба режима читают один непустой файл в штатном бинарном формате CIFAR-100 без заголовка. Каждая запись занимает 3074 байта: coarse-метка (0–19), fine-метка (0–99), затем по 1024 байта каналов R, G и B. В каждом канале пиксели идут по строкам, сверху вниз и слева направо. Метки не входят в признаки; в `eval` fine-метки нужны только после предсказания, для метрик и списка ошибок. Программа работает с локальными файлами, скачивать данные при запуске не нужно.

В обоих режимах пустой, усечённый или нечитаемый вход и метки вне диапазона — ошибки входных данных (`2`). Только в `eval` отсутствие, пустой файл или неверное содержимое чекпоинта также дают код `2`. Ни в одном режиме `--output` не должен указывать на вход, в том числе через ссылку; в `eval` он также не должен указывать на загруженные веса. При конфликте верните `1`, не открывая выход на запись. Укажите в README способ нормализации, seed и параметры обучения по умолчанию: проверка не передаёт дополнительных настроек обучения. Коды возврата и `--help` — по [общим правилам запуска](../docs/SUBMISSION_CONTRACT.md#cli-программы).

## Что проверяет раннер

Короткая GPU-проверка запускает `train` и затем `eval` на небольших синтетических наборах того же формата. Качество считаем по **top‑1 accuracy**: предсказанный класс совпал с эталонным или нет. Каждая пара `train → eval` должна пройти проверку отдельно: доля ошибок (`1 − accuracy`) на её отложенных изображениях не должна превышать 20% ошибки константного прогноза на тех же изображениях. Константа — самый частый класс в обучающем наборе этой пары, при равенстве берётся меньший класс. Это не порог итоговой точности на CIFAR-100 и не замена численным проверкам и профилированию из отчёта.

На каждый вызов `train` или `eval` раннер выделяет 1 CPU, 1024 МиБ RAM без дополнительного swap и до 60 секунд. Если `train` не завершился успешно за это время, зависимый `eval` не запускается. Раннер периодически измеряет VRAM; если процессы сдачи заняли больше 512 МиБ, он отправляет `SIGTERM`. Полное обучение в этот запуск не входит. Чтобы уложиться в лимиты, можно начать с более узкой сети, загружать на GPU по одному батчу и переиспользовать буферы. В чекпоинт достаточно записать параметры для `eval` (параметры базовой сети занимают около 18 МиБ в FP32), не датасет, активации или буферы оптимизатора.
