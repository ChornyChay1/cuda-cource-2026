# Lab 1. Vector Operations and Activations

## Описание

Подготовка к [Lab 1](../../lab1.md). Для каждой пары `x, y` программа должна
вычислять в FP32 три результата в исходном порядке: `x + y`, `alpha * x + y`
и `max(0, x)`. Оба режима используют одни и те же входные и выходные массивы.

Для сравнения памяти запланированы два способа распределить элементы одного
блока. В `coalesced` соседние потоки читают соседние элементы. В
`noncoalesced` локальный индекс потока `t` преобразуется по формуле
`(t % 32) * (blockDim.x / 32) + t / 32`. Соседние потоки варпа получают
шаг `blockDim.x / 32`, а каждый элемент обрабатывается ровно один раз.
Для этого эксперимента сравнивать блоки из 128, 256 и 512 потоков. После
перестановки проверять границу `index < N` в обоих режимах.

## Окружение

Для сборки нужны CMake 3.18 или новее, CUDA Toolkit с `nvcc` и совместимый
компилятор C++. Для контрольного запуска нужен GPU на Громозеке. Перед замерами
записать модель GPU, версию драйвера, CUDA и компилятора. Для самопроверки нужен
Python 3.8 или новее.

## Компиляция

Из каталога этой лабораторной:

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --target submission
```

## Запуск

Команды после реализации:

```bash
./build/submission --help
./build/submission --input input.txt --output output.txt --mode coalesced
./build/submission --input input.txt --output output.txt --mode noncoalesced
```

Во входном файле указать `N alpha`, затем `N` пар `x y`. Выход содержит три
числа на пару без заголовка. Режим по умолчанию — `coalesced`. Для `N=0`
запланирована запись пустого файла без запуска ядра.

## Проверка корректности

Проверка запускает оба режима и отдельно вызов без `--mode`. Она использует
пример курса и случаи на 0, 1, 255, 256, 257 и 1027 элементов со значениями
разных знаков и нулями. Ожидается точное совпадение на этих входах. Для
дополнительной проверки с произвольными FP32-входами использовать библиотечные
выражения, сохранить исходный `y` и учесть допустимое округление SAXPY с FMA.

## Результаты

После реализации прогреть GPU и записать число повторов и медиану замеров.
Измерить H2D, время ядра, D2H и полный цикл H2D → ядро → D2H. Время GPU
измерять событиями CUDA, полный цикл — таймером CPU с ожиданием завершения
GPU. Выделение памяти измерить отдельно. Сравнить оба режима при одинаковых
данных и конфигурациях блоков на массиве, существенно превышающем один блок.

## Выводы

По результатам замеров определить, как изменилось время ядра при доступе с
шагом и когда время передач превышает время вычислений.
