# Lab 1. Vector Operations and Activations

## Описание

[Задание Lab 1](../../lab1.md). Одно CUDA-ядро вычисляет три FP32-результата
на элемент: сложение `x + y`, SAXPY `alpha * x + y` через FMA и ReLU
`max(0, x)`. Входные `x` и `y` и три выходных столбца хранятся в отдельных
непрерывных областях памяти.

В режиме `coalesced` поток с локальным индексом `t = threadIdx.x` работает с
элементом `blockIdx.x * blockDim.x + t`. В режиме `noncoalesced` к началу
блока прибавляется `(t % 32) * (blockDim.x / 32) + t / 32`. Это перестановка
индексов внутри блока. Например, для блока из 256 потоков первый варп
обрабатывает элементы `0, 8, 16, …, 248` вместо `0, 1, …, 31`. После
вычисления индекса оба ядра проверяют `index < N`.

## Окружение

Для сборки нужны CMake 3.18 или новее, CUDA Toolkit с `nvcc` и совместимый
компилятор C++. Сборка проверена с CMake 4.4.5, CUDA 13.5.37 и GCC 14.2.0.
Для самопроверки нужен Python с NumPy. Для контрольного запуска на Громозеке
понадобится NVIDIA GPU. Модель GPU, драйвер и версии инструментов в окружении
замеров можно получить так:

```bash
nvidia-smi --query-gpu=name,driver_version --format=csv
nvcc --version
c++ --version
python3 -c 'import numpy; print(numpy.__version__)'
```

## Компиляция

Команды выполняются из каталога лабораторной.

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --target submission
```

## Запуск

```bash
printf '%s\n' '3 0.5' '-3 2' '1 -5' '4 0.5' > build/lab1.txt
./build/submission --help
./build/submission --input build/lab1.txt --output build/coalesced.txt
./build/submission --input build/lab1.txt --output build/noncoalesced.txt --mode noncoalesced
```

Во входном файле указываются `N alpha` и затем `N` пар `x y`. Выход
содержит по три числа на пару в исходном порядке и без заголовка. При `N=0`
создаётся пустой файл. Режим по умолчанию — `coalesced`.

Для замеров можно указать `--block-size 128|256|512` (по умолчанию 256) и
`--repeats N`, где `N` — положительное число замеров после трёх прогревочных
циклов. Без `--repeats` результат вычисляется один раз.

## Проверка корректности

```bash
python3 tests/check.py build/submission
```

| Вход | Режимы | Ожидаемый результат |
| --- | --- | --- |
| `N=0` | Оба и по умолчанию | Пустой файл |
| Пример курса, `N=3` | Оба и по умолчанию | Строки `-1 0.5 0`, `-4 -4.5 1`, `4.5 2.5 4` |
| `N=1, 255, 256, 257, 1027` | Оба и по умолчанию | Совпадение с FP32-выражениями NumPy |
| Случайный вход, `N=1031`, seed 42 | Оба с блоками 128, 256 и 512 | Совпадение с FP32-выражениями NumPy |

Скрипт использует одинаковые входы для программы и эталона и печатает
максимальную абсолютную ошибку для каждого столбца. Требуется точное совпадение
после чтения в FP32. Для SAXPY значение может совпадать с эталоном с FMA или с
раздельным округлением произведения и суммы. На Громозеке во всех 27 запусках
максимальная ошибка для каждой из трёх операций составила `0.0`. Также
проверены сборка, `--help`, пустой вход и обработка ошибок CLI.

## Результаты

Программа печатает медианы `H2D_ms`, `kernel_ms`, `D2H_ms` и `total_ms`.
Первые три интервала измеряются событиями CUDA в одном потоке. Полный цикл
измеряется таймером CPU от постановки операций в очередь до завершения
потока, включая накладные расходы постановки операций и событий. H2D и D2H
используют закреплённую память CPU. В `allocation_ms` отдельно измеряется
выделение буферов CPU и GPU. Чтение файла, перекладка входа по столбцам,
создание событий и запись результата вынесены из замеров цикла.

Скрипт `benchmark.py` запускает 18 конфигураций: три размера входа,
три размера блока и два режима доступа. Программа выполняет 30 замеров
после трёх прогревов на каждой конфигурации. Фактические времена нужно
снять на Громозеке.

## Выводы

При последовательной индексации варп обращается к соседним адресам. При
доступе с шагом те же значения распределены по большему числу участков
глобальной памяти, поэтому на уровне одного варпа требуется больше
транзакций. Фактический выигрыш зависит в том числе от повторного
использования данных в кэше. После замеров сравните `kernel_ms` между
режимами при одном блоке и проверьте, на каких размерах
`H2D_ms + D2H_ms` превышает `kernel_ms`.
