# Lab 1: Vector Operations and Activations

## Описание

Реализованы три CUDA-ядра для FP32-векторов: сложение, SAXPY (`alpha*x+y`) и ReLU. В `coalesced` соседние потоки обращаются к соседним элементам. В `noncoalesced` индексы переставляются внутри плитки 32×32: соседние потоки обращаются с шагом 32 float. Результаты обоих режимов записываются в исходном порядке.

Начальный индекс потока: `blockIdx.x * blockDim.x + threadIdx.x`. Дальше поток движется с шагом `blockDim.x * gridDim.x`. Граница массива проверяется после перестановки индекса. SAXPY использует исходный y и отдельные умножение и сложение FP32. Ошибки CUDA проверяются, память освобождается и при ошибках.

## Окружение

- GPU: NVIDIA GeForce RTX 3050 Laptop, 4 ГБ; драйвер 595.71.
- Ubuntu 24.04 в WSL2, CUDA Toolkit 12.6.85, GCC 13.3.0, CMake 3.28.3.
- Python 3.12, NumPy 2.3.2 — для проверки результатов.
- Сборка Release: C++17/CUDA17, `-O3 -DNDEBUG`, архитектура sm_86, без fast-math.

Все приведённые замеры локальные. Контрольный запуск на Громозеке пока не выполнен.

## Компиляция

Из каталога лабораторной, с установленным CUDA Toolkit:

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --target submission
```

При необходимости архитектура задаётся через `-DCMAKE_CUDA_ARCHITECTURES=86`. Локально использовались `-DCMAKE_CUDA_COMPILER="$PWD/build/cuda-toolkit/bin/nvcc"` и каталог сборки `build/wsl`; для этой сборки путь к программе — `build/wsl/submission`.

## Запуск

```bash
./build/submission --help
./build/submission --input data/example.txt --output build/result.txt
./build/submission --input data/example.txt --output build/result.txt --mode noncoalesced
./build/submission --input data/example.txt --output build/result.txt --experiments data/experiments.txt
```

Вход: `N alpha`, затем N пар `x y`. Выход: N строк `x+y alpha*x+y max(0,x)`, 9 значащих цифр. Для N=0 создаётся пустой файл. По умолчанию используется `coalesced` и один запуск с блоком 256 без прогрева.

В `data/experiments.txt` каждая строка задаёт размер блока, число прогревов и число измерений:

```text
128 10 50
256 10 50
512 10 50
```

С `--experiments` программа перебирает эти настройки без пересборки. В файл записывается результат последней настройки, в stdout — замеры каждой. Размер блока должен быть кратен 32 и лежать в диапазоне 32–1024, прогрев — неотрицательным, число измерений — положительным.

Ошибки выводятся в stderr. Коды возврата: 0 — успех, 2 — неверные аргументы или входные данные, 1 — ошибка выполнения или записи.

## Проверка корректности

Эталон — NumPy: `np.add`, `np.multiply` и `np.maximum`, все вычисления в FP32. Случайные входы генерируются в [-10,10] с seed=2026, alpha=-1.25; дополнительно проверяется пример задания с alpha=0.5. Исходный y одинаков для CUDA и эталона. Допуск — 0, максимальная ошибка всех трёх операций — 0.

| Проверка | Ожидалось | Получилось |
| --- | --- | --- |
| Пример N=3, alpha=0.5, оба режима | `(-1,0.5,0)`, `(-4,-4.5,1)`, `(4.5,2.5,4)` | Совпадает |
| N=0, оба режима | Пустой файл, код 0 | Выполнено |
| Маленькие размеры, нули, разные знаки, границы 32/128/256/512/1024 и N=65537 | Совпадение с NumPy в обоих режимах | Максимальная ошибка 0 |
| Неверные аргументы, вход и параметры эксперимента | Код 2 | Выполнено |
| Недоступный выходной каталог | Код 1 | Выполнено |

Скрипт `tests/validate.py` проверил 19 размеров × 2 режима × 3 размера блока: 114 сочетаний. Отдельно проверены режим по умолчанию и перебор всего файла настроек.

## Выводы

На большом массиве коалесцированный доступ ускорил три ядра примерно в 2.8–3.1 раза: соседние обращения требуют меньшего числа транзакций памяти. Это объяснение по организации адресов; аппаратные счётчики не измерялись.

Полный цикл ускоряется меньше, поскольку большую часть времени занимают передачи CPU↔GPU. На маленьком массиве вычисления занимают около 0.01 мс, а полный цикл — несколько десятых миллисекунды. Разброс замеров на ноутбуке не позволяет уверенно выбрать лучший размер блока. Значение 256 используется по умолчанию, но не считается оптимальным для любой GPU.

## Воспроизводимость

### Данные

`data/example.txt` — пример из задания. Скрипт сам создаёт временные тестовые входы с seed=2026 и удаляет их после проверки. С `--benchmark` дополнительно генерируются массивы из 257 и 1048576 элементов и запускаются оба режима со всеми настройками `data/experiments.txt`.

### Полный запуск

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --target submission
python3 -m venv build/venv
build/venv/bin/python -m pip install numpy==2.3.2
build/venv/bin/python tests/validate.py build/submission --benchmark --results build/validation.json
```

Для локальной WSL-сборки замените путь программы на `build/wsl/submission`. Полный отчёт проверки сохраняется в `build/validation.json`. Для других экспериментов достаточно изменить `data/experiments.txt` и повторить запуск.
